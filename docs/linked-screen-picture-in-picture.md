# Linked Screen 实时桌面画中画设计

本案以 iPhone 系统主屏幕为首要场景，也覆盖 AirPointer 自己的首页。交付目标是在 Mac 已授权共享、局域网正常、iOS 允许画中画时，切换界面沿用当前视频会话。以下是拟实施设计及验收目标。

## 用户怎么用

| 动作 | 用户看到的结果 |
| --- | --- |
| 首次共享 | 保留现有上方桌面、下方触控板。第一帧呈现后，工具行在全屏键旁提供系统画中画图标，辅助功能名称为 “Picture in Picture”。窄屏或键盘弹起时可从右上角更多菜单进入。 |
| 上滑回 iPhone 主屏幕 | 实时桌面缩成系统浮窗，可以打开其他 App。仅在桌面为当前主要内容、共享已开始、用户允许自动画中画时启用。更多菜单提供 “Start PiP on Home”，建议默认开启，首次共享时用一行说明告知。iOS 的系统设置优先。 |
| 主动点画中画 | 待系统确认浮窗已启动，再收起共享页，显示 AirPointer 首页。启动失败则留在原页并保留画面。 |
| 在浮窗里观看 | 按原比例完整显示所选 Mac 屏幕，保留已捕获的光标。窗口由 iOS 管理拖动、缩放和贴边。浮窗手势只操作播放器。 |
| 点浮窗的返回 App 按钮 | 回到同一块桌面，恢复原来的预览缩放和触控板布局。看到新鲜画面后才启用点击，键盘等用户再次点选 Mac 输入框时弹出。 |
| 点浮窗 × | 从后台或 AirPointer 首页关闭最后一个观看界面时结束共享，Mac 停止此会话。若共享页已在前台接手，继续在页内显示。 |
| 在共享页点 Close | 沿用结束共享的语义。画中画入口与结束操作使用不同图标和辅助功能描述。 |

首版在 App 首页展示当前设备及 “Return to Shared Screen”。返回共享页之前暂停首页遥控手势，避免在用户操作手机或浮窗时误控 Mac。结束共享后恢复原首页遥控功能。手表端沿用现有设备控制权规则。

## 工程落点

1. **会话归属。** 当前 ContentView 用 fullScreenCover 打开 LinkedScreenView，后者的 onDisappear 调用 client.end()。把 LinkedClient、显示层和画中画控制器交给 iPhone 根层持有，视图只订阅状态。显式结束、Mac 撤销共享及会话错误才清理相应资源。横竖屏、关闭 cover、还原 cover 都需复用同一实例。
2. **渲染。** LinkedDecoder 已把 H.264 封装成带主机时钟时间戳、立即显示的 CMSampleBuffer，LinkedClient.video 已经是 AVSampleBufferDisplayLayer。以该层创建 AVPictureInPictureController.ContentSource，接入 sample buffer playback delegate。维持有界帧队列、ACK 与原渲染路径，在 didStart 之前保持源视图挂载，还原时先挂回可见容器。验证显示层时间基准、恢复后首个可解码帧及异常 flush。一次共享只建一条视频连接。
3. **播放语义。** 按实时流提供无限时长的播放范围，启用线性播放，完成系统跳转回调。系统请求暂停时暂停视频，恢复时跳到实时位置并请求关键帧。播放状态改变后调用 invalidatePlaybackState。render size 回调用于观测，首版沿用前台编码规格，先验证切换流畅度。
4. **后台配置。** iPhone target 配置 Audio, AirPlay, and Picture in Picture 后台模式，核对最终产物的 UIBackgroundModes。按 AVKit 播放需求管理 AVAudioSession，随共享激活和释放。当前是无声桌面，真机检查与音乐、蓝牙耳机共存以及系统中断后恢复。能力检查分设备支持、当前可启动、系统已启动三个层次。[Apple PiP 控制器](https://developer.apple.com/documentation/avkit/avpictureinpicturecontroller) · [自动进入条件](https://developer.apple.com/documentation/avkit/avpictureinpicturecontroller/canstartpictureinpictureautomaticallyfrominline) · [直播播放代理](https://developer.apple.com/documentation/avkit/avpictureinpicturesamplebufferplaybackdelegate)
5. **两端生命周期。** 当前 LinkedClient.sceneChanged 在后台清除 live 状态，PhoneConnection.setForeground 同时通过 BLE 发后台心跳，Mac 的 PhoneReceiver 随后触发 LinkedHost.pauseForBackground。需将界面可操作、视频是否有人观看分开判断，两处都由同一会话策略驱动。共享握手协商新增“后台仅观看”能力，经既有认证通道向 Mac 切换权限。Mac 保持当前采集、编码和原有保活选择，释放按键、停止焦点探测并拒绝该客户端的输入。用已认证视频通道的活性检测回收失联会话，涵盖静止桌面无新帧的情况。真实撤权、配对失效和 Mac 主动停止始终终止共享。旧 Mac 缺少能力时保留现有前台共享，并提示更新接收端。

## 切换顺序与异常处理

| 阶段 | 处理 |
| --- | --- |
| 前台 → 即将离开 | 释放拖动和鼠标按下状态，清空待发移动、键盘自动弹出意图，保留本地草稿。短暂 inactive 也会由控制中心触发，仅凭该事件不能认定已进入后台。 |
| 请求或等待系统自动进入 | 在生命周期协调器中串行处理 scenePhase 和 PiP 代理事件。为符合条件的已有会话设置短暂、有截止时间的切换窗口，期间只观看。无论 background 与 willStart 谁先到，都避免抢先向 Mac 发普通暂停。 |
| didStart | 标记 PiP 活跃并取消切换超时，持续消费新帧和发送 ACK。只有手动从 App 内发起时才导航至首页。 |
| 启动失败、用户关闭自动进入或等候超时 | 已回后台则执行既有暂停策略，仍在前台则继续页内显示。记录原因，用户返回后可手动重试。 |
| 请求恢复 | 记录恢复意图，呈现对应会话的共享页。可见容器准备好后完成系统 restoration 回调。等前台、认证和新帧满足条件再恢复输入。延迟到达的 didStop 不应结束已接手的会话。 |
| 中断或结束 | 系统暂停浮窗、物理网络断开、Mac 休眠或撤权分别处理。可恢复的短暂中断进入有限等待，超时关闭浮窗并在 App 内说明原因。锁屏以暂停并释放输入为目标，验证锁屏与普通切后台的系统回调差异。结束路径幂等，按会话 ID 丢弃旧回调。 |

浮窗的系统播放/暂停只影响共享视频。不会向 Mac 上正在播放的应用发送媒体按键。已发送而结果不明的文本保留草稿并提示核对，恢复时需重新确认目标输入框。浮窗关闭后释放本次共享申请的防休眠资源。独立 Lid Desktop 工具继续负责虚拟显示器，画中画随当前所选真实或虚拟显示器工作。

## 实施与发布验收

| 阶段 | 实现与通过条件 |
| --- | --- |
| 1 · 端到端技术验证 | 先用真机手动画中画。Mac 显示持续跳秒的时钟，手机上滑回系统桌面并打开另一 App，观察时钟持续更新至少 5 分钟。验证系统确实允许当前无声直播持续收帧，并记录 BLE 生命周期、局域网 ACK 和显示层状态。 |
| 2 · 页面与自动切换 | 完成根层持有、能力协商、自动进入、恢复和显式结束。连续执行 20 次主页往返，统计切换间隔和恢复首帧时间。目标为正常网络下零重配对、零重新选屏、零重复连接；恢复首个新帧目标在 1 秒内。 |
| 3 · 输入回归 | 拖动窗口中上滑、中文输入中上滑、首页触控、返回时快速点击，逐项验证 Mac 没有卡住鼠标、误点或重复插入；重新点输入框能正常编辑。 |
| 4 · 异常与兼容 | 覆盖自动 PiP 关闭、已有其他 PiP、短暂打开控制中心、系统打断音频、锁屏、Wi-Fi 断开、Mac 停止共享、普通内建屏及 Lid Desktop 虚拟屏、旧版接收端。分别验证恢复或可理解的结束反馈。 |
| 5 · 性能与审核准备 | 在同一 Wi-Fi、同一动态桌面下比较前台与浮窗 10 分钟的帧间隔、ACK 延迟、内存和能耗。日志记录会话事件及计时，排除屏幕内容和输入文本。审核说明用英文写明配对、选屏、手动/自动 PiP、返回与停止步骤，说明后台能力服务于用户可见的实时桌面。 |

以上次数、时长及首帧阈值是建议验收标准，实际数据待实现后测量。

## 当前实现

- iPhone 的根页面持有桌面会话。共享页的画中画按钮可进入系统浮窗并回到 AirPointer 首页。自动进入采用系统画中画设置及共享菜单里的 “Start PiP on Home”。
- iPhone 和 Mac 在已认证的共享连接上协商画中画。仅观看、暂停播放和恢复交互走同一条连接。恢复交互时 Mac 发送新关键帧并等待确认，然后重新允许点击。
- 系统自动进入未完成时，使用短时后台任务把连接切回原有暂停流程。画中画活跃期间由共享连接心跳检测断开。
- iPhone 和 Mac 的 Xcode 构建已通过。现有联动共享和手机控制回归通过。后台连续播放、锁屏和系统还原交接仍以真机结果为准。
